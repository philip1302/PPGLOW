PPGlow-Hilfe

TPPGSearchEdit

Palette PPGlow - Unit PPG.SearchEdit - Basis TPPGCustomSearchEdit

Vorbild: TSearchBox (Vcl.WinXCtrls), WinUI AutoSuggestBox

Wofür

Das Suchfeld findet Datensätze, während der Anwender tippt: Kunden, Artikel, Belege. Nach einer kurzen Tipp-Pause (SearchDelay) meldet es OnSearch, die Anwendung füllt die Vorschläge oder filtert eine Liste. Enter, die Lupe oder die Wahl eines Vorschlags melden OnSubmit, dort wird der Treffer übernommen.

Wann verwenden

  • Für die Suche nach einem Datensatz in großen Beständen, die erst beim Tippen abgefragt werden (Kunden, Artikel). Für eine Auswahl aus einer festen, kurzen Liste ist TPPGComboBox klarer.
  • Als Filterfeld über einer Liste oder Tabelle: OnSearch filtert die Liste selbst, die Vorschlagsliste bleibt leer.
  • Statt TPPGEdit mit eigenem Timer, wenn nach einer Tipp-Pause gesucht werden soll. Für normale Texteingaben ohne Suche bleibt TPPGEdit richtig.
  • Für Stichwörter, von denen mehrere gleichzeitig gelten, ist TPPGTagEdit gedacht; das Suchfeld hält genau einen Suchbegriff.
  • Für die Auswahl eines Datensatzes aus einer Datenmenge mit Schlüsselfeld ist TPPGDBLookupComboBox gedacht; das Suchfeld liefert nur den Text, die Zuordnung macht die Anwendung in OnSubmit.

Unterschiede und Hinweise

  • Baut auf der ComboBox auf: Vorschläge in Items oder ItemsEx (mit Detailzeile, Bild, Plakette), Verzögerung SearchDelay über den gemeinsamen Animator (kein Timer), danach OnSearch.
  • Text im Code setzen löst weder OnSearch noch OnSubmit aus; FlushSearch führt eine wartende Suche sofort aus.
  • Enter und Esc gehen nicht an Default- und Cancel-Buttons des Dialogs: Enter sendet die Suche ab, Esc schließt die Liste bzw. leert das Feld.
  • OnInvokeSearch von TSearchBox (Enter oder Klick auf die Lupe) entspricht hier OnSubmit. Das Migrationsskript benennt es derzeit in OnSearch um; nach der Migration prüfen und den Handler bei Bedarf an OnSubmit hängen.

Verhalten (aus dem Quelltext)

TPPGSearchEdit - Suchfeld mit Vorschlagsliste (Phase 7a, wie WinUI AutoSuggestBox).

Basis ist die ComboBox (csDropDown): natives Edit, eigene Aufklappliste, Filter beim Tippen und Tastatur kommen von dort. Dazu:

  • Lupen-Button rechts (Klick = Suche absenden), Loeschen-Knopf, kein Aufklapp-Pfeil.
  • SearchDelay: Nach dem Tippen wartet das Feld SearchDelay ms (ueber den gemeinsamen Animator, kein Timer) und loest dann OnSearch aus. Dort kann die Anwendung Items (die Vorschlaege) neu fuellen; danach zeigt das Feld die Liste automatisch (gefiltert nach FilterMode).
  • Enter, Klick auf die Lupe oder Wahl eines Vorschlags loesen OnSubmit aus (sofort, eine wartende Suche entfaellt). Esc schliesst die Liste bzw. leert den Text.
  • Text im Code setzen loest weder OnSearch noch OnSubmit aus.

OnKeyPressTKeyPressEvent (Sender: TObject; var Key: Char)Zeichen eingegeben; Key := #0 verwirft es. Praxis: Um unerwünschte Zeichen zu verwerfen (Key := #0), z. B. bei einer Suche nur nach Ziffern.
OnKeyUpTKeyEvent (Sender: TObject; var Key: Word; Shift: TShiftState)Taste losgelassen. Praxis: Selten gebraucht; die Reaktion auf getippten Text gehört in OnChange bzw. OnSearch.
OnMouseEnterTNotifyEvent (Sender: TObject)Die Maus ist in das Control hineinbewegt worden. Praxis: Um beim Überfahren eine Erklärung in der Statusleiste zu zeigen, wonach man suchen kann.
OnMouseLeaveTNotifyEvent (Sender: TObject)Die Maus hat das Control verlassen. Praxis: Gegenstück zu OnMouseEnter: die Erklärung wieder ausblenden.
OnSearchTPPGSearchEvent (Sender: TObject; const SearchText: string)SearchDelay ms nach der letzten Eingabe mit dem Suchtext; hier die Vorschläge (Items) neu füllen, danach zeigt das Feld die Liste. Text im Code löst es nicht aus. Nutzung: Search.Items.Assign(SucheKunden(SearchText)); Praxis: Hier die Vorschläge holen: Datenbank abfragen und Items bzw. ItemsEx füllen. Erst ab zwei Zeichen suchen, sonst wird die Liste zu lang; bei leerem Text die Vorschläge leeren.
OnSelectTNotifyEvent (Sender: TObject)Der Anwender hat einen Eintrag gewählt (Klick, Enter, Pfeiltasten im geschlossenen Feld). Kommt nach OnClick; ist OnSelect nicht zugewiesen, wird stattdessen OnChange ausgelöst. Nicht bei ItemIndex aus Code. Praxis: Wenn die Wahl eines Vorschlags anders behandelt wird als eine frei getippte Suche, z. B. den Datensatz direkt öffnen. Für beides gemeinsam reicht OnSubmit.
OnSubmitTPPGSearchEvent (Sender: TObject; const SearchText: string)Suche abgeschickt: Enter, Klick auf die Lupe oder Wahl eines Vorschlags. Eine noch wartende OnSearch-Suche entfällt. Nutzung: ZeigeErgebnisse(SearchText); Praxis: Hier die Suche ausführen bzw. den Treffer übernehmen: Ergebnisliste füllen, Datensatz öffnen. Kommt bei Enter, Klick auf die Lupe und Wahl eines Vorschlags.
OnClickTNotifyEvent (Sender: TObject)Klick mit der linken Maustaste, Leertaste/Enter bei Buttons oder Auslösen per Zugriffstaste. Bei Listen, Baum, Grid, Auswahlgruppen und Aufklapp-Auswahlfeldern (ComboBox, ColorPicker, ColumnComboBox, CheckComboBox) meldet OnClick wie in der VCL die Auswahl durch den Anwender. Praxis: Selten gebraucht; das Suchfeld meldet den Klick ins Feld. Für das Absenden (Lupe, Enter, Vorschlag) ist OnSubmit da.
OnDblClickTNotifyEvent (Sender: TObject)Doppelklick mit der linken Maustaste. Controls, bei denen schnelle Klicks einzeln zählen (Button, CheckBox, ToggleSwitch, Rating, ToolBar …), haben es wie TButton nicht. Praxis: Selten gebraucht; ein Doppelklick markiert im Feld ein Wort. Nicht für Aktionen nutzen, die der Anwender nicht erwartet.
OnMouseDownTMouseEvent (Sender: TObject; Button: TMouseButton; Shift: TShiftState; X, Y: Integer)Maustaste über dem Control gedrückt. Praxis: Selten gebraucht; Lupe und Löschen-Knopf arbeiten ohne eigenen Code.
OnMouseMoveTMouseMoveEvent (Sender: TObject; Shift: TShiftState; X, Y: Integer)Maus über dem Control bewegt. Praxis: Selten gebraucht; feuert bei jeder Mausbewegung über dem Feld.
OnMouseUpTMouseEvent (Sender: TObject; Button: TMouseButton; Shift: TShiftState; X, Y: Integer)Maustaste über dem Control losgelassen. Praxis: Selten gebraucht; für das Absenden der Suche OnSubmit nehmen.
OnMouseWheelTMouseWheelEvent (Sender: TObject; Shift: TShiftState; WheelDelta: Integer; MousePos: TPoint; var Handled: Boolean)Mausrad gedreht; Handled := True verhindert das Standard-Scrollen. Praxis: Selten gebraucht; Handled := True verhindert, dass das Rad über dem Feld den Parent scrollt.
OnMouseActivateTMouseActivateEvent (Sender: TObject; Button: TMouseButton; Shift: TShiftState; X, Y, HitTest: Integer; var MouseActivate: TMouseActivate)Mausklick auf ein noch inaktives Fenster; legt fest, ob es aktiviert wird. Praxis: Nur in Spezialfällen (Werkzeugfenster) ändern; sonst nicht belegen.
OnDragDropTDragDropEvent (Sender, Source: TObject; X, Y: Integer)Ein gezogenes Objekt wurde über dem Control losgelassen. Nutzung: Source ist das gezogene Control; X, Y die Position im Control. Praxis: Wenn ein Begriff aus einer Liste ins Suchfeld gezogen werden darf: hier den Text übernehmen und die Suche starten.
OnDragOverTDragOverEvent (Sender, Source: TObject; X, Y: Integer; State: TDragState; var Accept: Boolean)Ein Objekt wird über dem Control gezogen; Accept := True erlaubt das Ablegen. Praxis: Zusammen mit OnDragDrop: Accept := Source is TPPGListBox erlaubt das Ablegen nur aus passenden Listen.
OnStartDragTStartDragEvent (Sender: TObject; var DragObject: TDragObject)Beginn des Ziehens dieses Controls; hier kann ein eigenes DragObject gesetzt werden. Praxis: Nur bei DragMode = dmAutomatic; beim Suchfeld praktisch nie gebraucht.
OnEndDragTEndDragEvent (Sender, Target: TObject; X, Y: Integer)Ziehen dieses Controls beendet (abgelegt oder abgebrochen; Target = nil bei Abbruch). Praxis: Nur bei DragMode = dmAutomatic; beim Suchfeld praktisch nie gebraucht.
