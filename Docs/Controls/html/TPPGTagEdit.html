PPGlow-Hilfe

TPPGTagEdit

Palette PPGlow - Unit PPG.TagEdit - Basis TPPGCustomDropDownField

Vorbild: Empfängerfeld von Outlook, WinUI TokenizingTextBox

Wofür

Das TagEdit nimmt mehrere kurze Werte in einem Feld auf und zeigt jeden als Chip mit Kreuz: Empfänger einer E-Mail, Schlagworte eines Tickets, Fähigkeiten eines Mitarbeiters. Der Anwender tippt, bestätigt mit Enter oder ; und wählt aus Vorschlägen. Im Code stehen die Werte als Liste (Tags) oder als ein Text für ein Datenbankfeld (TagsText).

Wann verwenden

  • Für mehrere frei eingegebene Werte, die einzeln entfernt werden sollen (Empfänger, Schlagworte). Für einen einzelnen Wert ist TPPGEdit oder TPPGComboBox einfacher.
  • Statt TPPGCheckComboBox, wenn die Auswahl klein ist, die Liste aber lang oder offen: Das TagEdit zeigt nur das Gewählte, die CheckComboBox alle Einträge zum Ankreuzen. Bei wenigen festen Optionen ist die CheckComboBox oder eine TPPGCheckListBox übersichtlicher.
  • Mit AllowNew = False als platzsparende Mehrfachauswahl aus einer festen Liste (Kategorien, Abteilungen), wenn der Anwender lieber tippt als blättert.
  • Für Datenbankfelder mit mehreren Werten in einer Spalte die DB-Variante TPPGDBTagEdit nehmen (Wert = TagsText).

Unterschiede und Hinweise

  • Chips (Text mit ×) stehen vor dem Eingabebereich und brechen über mehrere Zeilen um. Mit AutoSize wächst die Höhe mit. Das Layout wird nur bei Änderung der Tags, der Breite oder der Schrift neu berechnet.
  • Ein Tag entsteht:
  • mit Enter
  • mit einem Zeichen aus InputDelimiters (; ,)
  • beim Verlassen (AddOnExit)
  • eingefügtes a; b; c ergibt drei Tags
  • Rücktaste im leeren Feld markiert zuerst das letzte Tag und löscht es beim zweiten Druck (wie Outlook). Pfeil links/rechts wandert zwischen den Chips, Entf löscht das markierte.
  • Suggestions erscheinen während des Tippens. Mit AllowNew = False sind nur Vorschläge erlaubt. Doppelte sind ausgeschlossen (AllowDuplicates, CaseSensitive); MaxTags begrenzt die Anzahl.
  • OnTagAdding kann ablehnen oder den Text ändern (z. B. eine E-Mail prüfen). Dazu kommen OnTagRemoved und OnTagClick. Code (Tags, TagsText) löst nichts aus.
  • Screenreader: Die Chips sind Kinder; die Standardaktion ist Entfernen.

Beispiel

PPGTagEdit1.Suggestions.CommaText := 'Delphi,VCL,Windows';
PPGTagEdit1.TagsText := 'Delphi;VCL';

Verhalten (aus dem Quelltext)

TPPGTagEdit - Stichwoerter als Chips (Phase 12f, Vorbild Outlook-Empfaenger, WinUI TokenizingTextBox).

  • Chips (Text mit x) vor dem Eingabebereich, Umbruch ueber mehrere Zeilen; mit AutoSize waechst die Hoehe mit. Das Layout wird nur bei Aenderung der Tags, der Breite oder der Schrift berechnet (nicht je Tastendruck).
  • Ein Tag entsteht mit Enter, mit einem der Delimiters (";" ",") oder beim Verlassen (AddOnExit). Eingefuegtes "a; b; c" ergibt drei Tags.
  • Ruecktaste im leeren Feld markiert zuerst das letzte Tag und loescht es beim zweiten Druck (wie Outlook); Pfeil links/rechts wandert zwischen den Chips, Entf loescht das markierte.
  • Vorschlaege (Suggestions) im Aufklapp-Fenster waehrend des Tippens; AllowNew = False erlaubt nur Vorschlaege. MaxTags, CaseSensitive, keine Doppelten.
  • Ereignisse nur bei Anwenderaktionen: OnTagAdding (abbrechbar, Text aenderbar - z.B. E-Mail pruefen), OnTagRemoved, OnTagClick, OnChange. Tags aus Code (Tags.Add, TagsText) loesen nichts aus.
  • Screenreader: Chips als Kinder, Standardaktion Entfernen.

PPGlow-Eigenschaften

Verlinkte Typen haben eine eigene Seite mit allen Untereigenschaften.

EigenschaftTypVorgabeWirkung und Nutzung
TagsTStringsDie aktuellen Tags, je Zeile eines. Änderungen aus Code lösen keine Ereignisse aus. Nutzung: TagEdit1.Tags.Add('Wichtig'); Praxis: Die eingetragenen Werte lesen oder vorbelegen, z. B. die Empfänger einer E-Mail oder die Schlagworte eines Datensatzes. Beim Laden aus der Datenbank Tags bzw. TagsText setzen; das löst bewusst keine Ereignisse aus.
SuggestionsTStringsVorschläge, die beim Tippen im Aufklappfenster erscheinen. Nutzung: TagEdit1.Suggestions.CommaText := 'Vertrieb,Einkauf,Technik'; Praxis: Mit den bekannten Werten füllen, z. B. Adressen aus dem Adressbuch oder die erlaubten Kategorien. Der Anwender tippt „ver“ und wählt „Vertrieb“, statt es auszuschreiben; bei langen Listen beim Öffnen des Formulars einmal laden.
InputDelimitersstringZeichen, die beim Tippen ein Tag abschließen (z. B. „;," ). Enter schließt immer ab; eingefügtes „a; b; c" ergibt drei Tags. Praxis: „;,“ lassen, wenn Anwender Adresslisten aus Outlook oder Excel einfügen. Für Schlagworte mit Komma im Text (z. B. „Müller, Hans“) nur „;“ eintragen, für reine Enter-Bestätigung leer lassen.
DelimiterChar';'Trennzeichen der Tags in TagsText bzw. im DB-Feld. Vorgabe „;". Praxis: Trennzeichen für das Datenbankfeld bzw. TagsText; „;“ passt zu den meisten Adress- und Schlagwortlisten. Wählen Sie ein Zeichen, das in den Werten selbst nie vorkommt.
AllowNewBooleanTrueFalse: Nur Einträge aus Suggestions sind erlaubt (Auswahlliste statt freier Eingabe). Praxis: False für feste Auswahllisten wie Kategorien, Abteilungen oder Status: Dann landen keine Tippfehler in der Datenbank. True für freie Schlagworte und E-Mail-Adressen.
AllowDuplicatesBooleanFalseTrue: Dasselbe Tag darf mehrfach vorkommen. Praxis: Fast immer False lassen: Zwei gleiche Empfänger oder Schlagworte sind ein Versehen. True nur, wenn die Wiederholung etwas bedeutet, z. B. Mengen als Einträge.
CaseSensitiveBooleanFalseTrue: Groß-/Kleinschreibung zählt beim Prüfen auf Doppelte und beim Abgleich mit Suggestions. Praxis: False lassen, damit „Vertrieb“ und „vertrieb“ als dasselbe Tag gelten. True nur bei Werten, bei denen die Schreibweise zählt, z. B. Artikelcodes.
MaxTagsInteger0Höchstzahl der Tags; 0 = ohne Grenze. Praxis: Begrenzt die Auswahl, wo das Fachliche eine Grenze hat, z. B. höchstens 5 Empfänger oder 3 Schwerpunkte je Mitarbeiter. 0 lassen, wenn es keine Grenze gibt.
AddOnExitBooleanTrueTrue: Beim Verlassen des Felds wird angefangener Text zum Tag. Praxis: True lassen, damit eine angefangene Eingabe beim Klick auf „Speichern“ nicht verloren geht. False, wenn nur ausdrücklich bestätigte Einträge (Enter) zählen sollen.
PresetstringOptik-Vorlage: „Classic" (glänzend, Office-Stil), „ModernFlat" (flach mit Glow, Standard) oder „Fluent11" (Windows 11) sowie selbst registrierte Renderer. Beim Wechsel übernimmt Appearance die Farben und Formen der Vorlage. Ein unbekannter Name löst zur Laufzeit EPPGPropertyError aus; beim Laden einer DFM wird auf den Standard zurückgefallen. Das Standard-Preset wird nicht in der DFM gespeichert. Nutzung: PPGButton1.Preset := 'Fluent11'; Für alle Controls eines Formulars einheitlich über StyleManager. Praxis: Legen Sie die Optik einmal für die ganze Anwendung fest, am besten über einen TPPGStyleManager. Dann sehen TagEdit, Edit und ComboBox im Formular gleich aus.
StyleManagerTPPGStyleManagerZentrale Stilquelle (TPPGStyleManager). Ist sie gesetzt, kommen Preset, Appearance und Animation vom Manager; eigene Werte des Controls gelten dann nicht. Nutzung: Einen TPPGStyleManager aufs Formular legen und bei allen Controls zuweisen. Praxis: Einen TPPGStyleManager aufs Formular legen und allen Feldern zuweisen; dann wechseln Optik und Hell/Dunkel für alle Eingabefelder auf einmal.
AppearanceTPPGAppearanceAussehen je Zustand: Farben, Verläufe, Rand, Glow und Textfarbe für Normal, Hot (Maus darüber), Down (gedrückt), Disabled und Checked, dazu Rundung, Randbreite, Glow-Größe, Fokusfarbe, eigene Fokus- und Dunkel-Farben. Wird beim Preset-Wechsel neu befüllt. In der DFM stehen nur die Werte, die vom Preset abweichen; der Rest kommt beim Laden aus dem Preset. Nutzung: PPGButton1.Appearance.Normal.Color := $00F0E0D0; PPGButton1.Appearance.Rounding := 8; Praxis: Für einzelne Hervorhebungen, z. B. einen kräftigeren Fokusrand in Pflichtfeldern. Für eine einheitliche Optik besser Preset bzw. StyleManager.
AnimationTPPGAnimationSettingsÜbergänge zwischen den Zuständen (Hover, Drücken, Fokus): an/aus, Dauer und ob die Windows-Einstellung „Animationen anzeigen" beachtet wird. Praxis: An lassen; Fokus- und Hover-Übergänge wirken ruhiger. RespectSystemSettings beachtet die Windows-Einstellung „Animationen anzeigen“.
TextHintstringPlatzhaltertext im leeren Feld (z. B. „Suchen …"). Nutzung: Edit1.TextHint := 'E-Mail-Adresse'; Praxis: Sagt, was eingegeben wird, z. B. „Name oder E-Mail-Adresse“ oder „Schlagwort tippen …“. Er erscheint nur, solange noch kein Text getippt ist.
ValidationStateTPPGValidationStatepvsNoneErgebnis einer Prüfung: pvsNone (neutral), pvsValid (grüner Rand), pvsWarning (gelb), pvsError (rot). Die Farben kommen aus den Signal-Tokens; ValidationHint erklärt den Zustand. Werte: pvsNone, pvsValid, pvsWarning, pvsError. Nutzung: if not IstMail(Edit1.Text) then begin Edit1.ValidationState := pvsError; Edit1.ValidationHint := 'Keine gültige Adresse'; end; Praxis: pvsError, wenn ein Eintrag abgelehnt wurde oder ein Pflichtfeld leer ist; pvsNone, sobald alles stimmt. Den Grund schreiben Sie in ValidationHint.
ValidationHintstringErklärung zum ValidationState; erscheint als Tooltip und wird vom Screenreader vorgelesen. Praxis: Erklärt den roten Rand in einem Satz, z. B. „Keine E-Mail-Adresse: max huber“. Er erscheint als Tooltip und wird vom Screenreader vorgelesen.
HighContrastSupportBooleanTrueTrue: Im Windows-Hochkontrastmodus verwendet das Control die Systemfarben statt der eigenen Farben (empfohlen für Barrierefreiheit). Praxis: True lassen: Sehbehinderte Anwender mit Hochkontrast sehen Rand und Chips dann in klaren Systemfarben.
BorderStyleTBorderStylebsSinglebsSingle: Rahmen nach Appearance; bsNone: ohne Rahmen (z. B. eingebettet in eigene Flächen). Praxis: bsSingle für normale Formularfelder. bsNone, wenn das Feld in eine eigene Fläche eingebettet ist, z. B. als Empfängerzeile in einem Mail-Kopf ohne eigene Rahmen.
ReadOnlyBooleanFalseTrue: Der Text kann gelesen, markiert und kopiert, aber nicht geändert werden. Die Optik bestimmt ReadOnlyStyle. Praxis: Für Datensätze, die man sehen, aber nicht ändern darf, z. B. abgeschlossene Tickets oder fehlende Schreibrechte. Die Tags bleiben lesbar, Kreuz und Eingabe sind gesperrt.
ReadOnlyStyleTPPGElementStyleEigene Optik bei ReadOnly: Fläche, Text- und Randfarbe (je auch für Dunkel). clDefault = wie im bearbeitbaren Zustand. Nutzung: Edit1.ReadOnlyStyle.Color := $00F0F0F0; Edit1.ReadOnlyStyle.TextColor := clGrayText; Praxis: Wenn gesperrte Felder deutlich anders aussehen sollen als bearbeitbare, z. B. mit grauer Fläche. clDefault lassen, wenn die Optik des Presets reicht.
TabStopBooleanTrueTrue: Das Feld ist mit Tab erreichbar. Praxis: True lassen, damit das Feld per Tab erreichbar ist; Tags werden dann komplett per Tastatur bearbeitet (Enter, Rücktaste, Pfeile).
ShowClearButtonBooleanFalseTrue: Ein „×"-Knopf im Feld löscht den Text (nur sichtbar, wenn Text vorhanden und das Feld bearbeitbar ist). Praxis: True bei Filterfeldern, damit der Anwender alle Tags auf einmal entfernen kann. In Datenformularen eher aus, dort entfernt man einzeln über das Kreuz am Chip.
TextHintVisibleOnFocusBooleanFalseTrue: Der Platzhalter bleibt sichtbar, bis getippt wird; False: er verschwindet schon beim Fokus. Praxis: True, wenn der Platzhalter eine Anleitung enthält („Adresse eingeben und Enter drücken“), die man beim Hineinklicken noch lesen soll.

Ereignisse

EreignisTyp und ParameterWann und wozu
OnTagAddingTPPGTagAddingEvent (Sender: TObject; var Tag: string; var Allow: Boolean)Bevor ein Tag durch den Anwender entsteht: Tag kann geändert (z. B. getrimmt) werden, Allow := False lehnt ab. Nutzung: Allow := Pos('@', Tag) > 0; // nur E-Mail-Adressen Praxis: Hier prüfen und vereinheitlichen Sie jeden neuen Eintrag: Tag := LowerCase(Tag) für E-Mail-Adressen, Allow := False bei ungültigen Werten. Abgelehnter Text bleibt im Feld stehen, damit der Anwender ihn korrigieren kann.
OnTagRemovedTPPGTagEvent (Sender: TObject; const Tag: string)Der Anwender hat ein Tag entfernt (Klick auf ×, Entf oder Rücktaste). Praxis: Um auf das Entfernen zu reagieren, z. B. abhängige Felder leeren oder in der Statuszeile „Anna Berger entfernt“ melden.
OnTagClickTPPGTagEvent (Sender: TObject; const Tag: string)Ein Tag (Chip) wurde angeklickt. Praxis: Um ein Tag als Verweis zu nutzen: nach dem Schlagwort filtern oder zum Empfänger die Kontaktkarte öffnen.
OnGestureTGestureEvent (Sender: TObject; const EventInfo: TGestureEventInfo; var Handled: Boolean)Eine Touch- oder Mausgeste wurde erkannt (siehe Touch). EventInfo.GestureID nennt die Geste; Handled := True beendet die Standardbehandlung. Nutzung: if EventInfo.GestureID = sgiLeft then NaechsteSeite; Praxis: Auf Touch-Geräten: Wischgesten auswerten (EventInfo.GestureID); für die normale Eingabe nicht nötig.
OnChangeTNotifyEvent (Sender: TObject)Der Anwender hat Tags hinzugefügt oder entfernt (auch über den Löschknopf). Tippen ohne neues Tag und Änderungen aus Code (Tags, TagsText) lösen es nicht aus. Praxis: Feuert, wenn der Anwender Tags hinzufügt oder entfernt (nicht beim Tippen und nicht bei Änderungen aus Code). Der richtige Ort, um z. B. „Senden“ freizugeben oder einen Zähler zu aktualisieren.
OnEnterTNotifyEvent (Sender: TObject)Das Control hat den Fokus erhalten. Praxis: Für Hilfetexte in der Statusleiste („Mehrere Adressen mit ; trennen“), sobald das Feld den Fokus bekommt.
OnExitTNotifyEvent (Sender: TObject)Das Control hat den Fokus verloren; guter Ort für Prüfungen der Eingabe. Praxis: Guter Ort für die Pflichtfeld-Prüfung: Tags.Count = 0 → ValidationState := pvsError. Angefangener Text ist dank AddOnExit zu diesem Zeitpunkt schon ein Tag.
OnKeyDownTKeyEvent (Sender: TObject; var Key: Word; Shift: TShiftState)Taste gedrückt (auch Sondertasten wie Pfeile, F-Tasten); Key := 0 verwirft sie. Nutzung: if Key = VK_RETURN then Speichern; Praxis: Für zusätzliche Tasten, z. B. Strg+K öffnet das Adressbuch. Enter, Rücktaste, Entf und Pfeile erledigt das Feld schon selbst.
OnKeyPressTKeyPressEvent (Sender: TObject; var Key: Char)Zeichen eingegeben; Key := #0 verwirft es. Praxis: Um Zeichen zu verwerfen, die in Tags nicht vorkommen dürfen, z. B. Key := #0 bei Leerzeichen in Artikelcodes.
OnKeyUpTKeyEvent (Sender: TObject; var Key: Word; Shift: TShiftState)Taste losgelassen. Praxis: Selten nötig; z. B. für eine eigene Live-Suche nach jedem Tastendruck.
OnClickTNotifyEvent (Sender: TObject)Klick mit der linken Maustaste, Leertaste/Enter bei Buttons oder Auslösen per Zugriffstaste. Bei Listen, Baum, Grid, Auswahlgruppen und Aufklapp-Auswahlfeldern (ComboBox, ColorPicker, ColumnComboBox, CheckComboBox) meldet OnClick wie in der VCL die Auswahl durch den Anwender. Praxis: Selten nötig; feuert beim Klick in das Feld. Für Klicks auf einen Chip nehmen Sie OnTagClick.
OnDblClickTNotifyEvent (Sender: TObject)Doppelklick mit der linken Maustaste. Controls, bei denen schnelle Klicks einzeln zählen (Button, CheckBox, ToggleSwitch, Rating, ToolBar …), haben es wie TButton nicht. Praxis: Selten nötig, z. B. um bei Doppelklick in das leere Feld ein Auswahlfenster (Adressbuch) zu öffnen.
OnMouseDownTMouseEvent (Sender: TObject; Button: TMouseButton; Shift: TShiftState; X, Y: Integer)Maustaste über dem Control gedrückt. Praxis: Selten nötig; Klicks auf Chips und Kreuz behandelt das Feld selbst (OnTagClick, OnTagRemoved).
OnMouseMoveTMouseMoveEvent (Sender: TObject; Shift: TShiftState; X, Y: Integer)Maus über dem Control bewegt. Praxis: Selten nötig; feuert bei jeder Mausbewegung. Hervorhebung der Chips und des Kreuzes macht das Feld selbst.
OnMouseUpTMouseEvent (Sender: TObject; Button: TMouseButton; Shift: TShiftState; X, Y: Integer)Maustaste über dem Control losgelassen. Praxis: Gegenstück zu OnMouseDown; für Aktionen auf Chips besser OnTagClick nehmen.
OnMouseEnterTNotifyEvent (Sender: TObject)Die Maus ist in das Control hineinbewegt worden. Praxis: Um beim Überfahren eine Erklärung in der Statuszeile zu zeigen; die Hover-Optik macht das Feld selbst.
OnMouseLeaveTNotifyEvent (Sender: TObject)Die Maus hat das Control verlassen. Praxis: Gegenstück zu OnMouseEnter: Erklärung wieder ausblenden.
OnMouseWheelTMouseWheelEvent (Sender: TObject; Shift: TShiftState; WheelDelta: Integer; MousePos: TPoint; var Handled: Boolean)Mausrad gedreht; Handled := True verhindert das Standard-Scrollen. Praxis: Selten nötig; Handled := True verhindert, dass der Parent scrollt.
OnMouseActivateTMouseActivateEvent (Sender: TObject; Button: TMouseButton; Shift: TShiftState; X, Y, HitTest: Integer; var MouseActivate: TMouseActivate)Mausklick auf ein noch inaktives Fenster; legt fest, ob es aktiviert wird. Praxis: Nur in Spezialfällen (Werkzeugfenster) ändern; sonst nicht belegen.
OnContextPopupTContextPopupEvent (Sender: TObject; MousePos: TPoint; var Handled: Boolean)Vor dem Kontextmenü; Handled := True unterdrückt das Standardmenü. Praxis: Um das Kontextmenü vor dem Öffnen anzupassen, z. B. „Entfernen“ nur bei markiertem Tag freigeben, oder mit Handled := True zu unterdrücken.
OnDragDropTDragDropEvent (Sender, Source: TObject; X, Y: Integer)Ein gezogenes Objekt wurde über dem Control losgelassen. Nutzung: Source ist das gezogene Control; X, Y die Position im Control. Praxis: Zum Ablegen auf das Feld, z. B. Kontakte aus einer Liste als Empfänger hinzufügen: hier TagEdit.Tags.Add oder AddTag mit dem gezogenen Wert.
OnDragOverTDragOverEvent (Sender, Source: TObject; X, Y: Integer; State: TDragState; var Accept: Boolean)Ein Objekt wird über dem Control gezogen; Accept := True erlaubt das Ablegen. Praxis: Zusammen mit OnDragDrop: Accept := Source = lstKontakte erlaubt das Ablegen nur aus der passenden Liste.
OnStartDragTStartDragEvent (Sender: TObject; var DragObject: TDragObject)Beginn des Ziehens dieses Controls; hier kann ein eigenes DragObject gesetzt werden. Praxis: Nur wenn das Feld selbst gezogen wird: ein eigenes DragObject setzen, z. B. mit allen Tags als Text.
OnEndDragTEndDragEvent (Sender, Target: TObject; X, Y: Integer)Ziehen dieses Controls beendet (abgelegt oder abgebrochen; Target = nil bei Abbruch). Praxis: Nur wenn das Feld selbst gezogen wird (DragMode); Target = nil heißt abgebrochen.
