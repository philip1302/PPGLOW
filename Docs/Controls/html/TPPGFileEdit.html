PPGlow-Hilfe

TPPGFileEdit

Palette PPGlow - Unit PPG.FileEdit - Basis TPPGCustomFileEdit

Vorbild: TMS TAdvFileNameEdit / TAdvDirectoryEdit

Wofür

Das Dateifeld nimmt einen Pfad auf: eine Datei zum Öffnen, ein Speicherziel oder einen Ordner. Der Anwender tippt den Pfad (mit Autovervollständigung), wählt ihn über den Knopf im Feld oder zieht ihn aus dem Explorer hinein. Es ersetzt die übliche Kombination aus TEdit, „…“-Button und TOpenDialog in einem Control.

Wann verwenden

  • Für Pfade in Import-, Export- und Einstellungsdialogen: Quelldatei, Speicherziel, Arbeits- oder Sicherungsordner.
  • Statt TPPGEdit mit eigenem Durchsuchen-Button: Dialog, Filter, Ablegen und Existenzprüfung (MustExist) sind schon eingebaut.
  • Statt eines einzelnen TOpenDialog hinter einem Button, wenn der Pfad sichtbar bleiben und gespeichert werden soll. Für einen einmaligen Befehl „Datei öffnen …“ reicht der Dialog allein.
  • Nicht für mehrere Dateien auf einmal: Das Feld hält genau einen Pfad. Für Listen von Anhängen eine Liste mit eigenem Hinzufügen-Button nehmen.

Unterschiede und Hinweise

  • Kind: Datei öffnen, Datei speichern oder Ordner.
  • Der Knopf im Feld (oder Alt+Pfeil runter, F4) öffnet ab Vista TFileOpenDialog/TFileSaveDialog. Davor gibt es TOpenDialog/TSaveDialog, für Ordner SHBrowseForFolder. Filter im VCL-Format wird in Dateitypen umgesetzt.
  • Dateien aus dem Explorer lassen sich ablegen: Es zählt die erste Datei bzw. der erste Ordner, der zu Kind passt.
  • Die Autovervollständigung von Pfaden kommt von Windows (SHAutoComplete).
  • MustExist: Eine fehlende Datei bzw. ein fehlender Ordner steht beim Verlassen als Fehler am Feld. Ein leeres Feld ist gültig.
  • OnBeforeDialog kann den Dialog abbrechen, OnAfterDialog den gewählten Namen ändern oder ablehnen.

Beispiel

PPGFileEdit1.Kind := fkOpenFile;
PPGFileEdit1.Filter := 'Dokumente|*.pdf;*.docx|Alle Dateien|*.*';
PPGFileEdit1.MustExist := True;

Verhalten (aus dem Quelltext)

TPPGFileEdit - Feld fuer eine Datei oder einen Ordner (Phase 12c).

  • Kind: Datei oeffnen, Datei speichern oder Ordner. Der Knopf im Feld oeffnet ab Vista TFileOpenDialog/TFileSaveDialog (Ordner ueber fdoPickFolders), davor TOpenDialog/TSaveDialog bzw. SHBrowseForFolder (Laufzeitpruefung, XE2 auf XP).
  • Ablegen aus dem Explorer (DragAcceptFiles/WM_DROPFILES): die erste Datei bzw. der erste Ordner passend zu Kind.
  • Autovervollstaendigung von Pfaden ueber SHAutoComplete auf dem inneren Edit (dynamisch geladen; ohne Shell-Funktion einfach ohne).
  • MustExist: fehlende Datei bzw. fehlender Ordner beim Verlassen als ValidationState (kein Dialog). Leeres Feld ist gueltig.
  • Ereignisse: OnBeforeDialog (abbrechbar, Dialog vorbereiten), OnAfterDialog (Name pruefen/aendern), OnChange wie beim Edit.

Nutzung: if Key = VK_RETURN then Speichern; Praxis: Für eigene Tasten im Feld, z. B. Enter startet den Import. F4 und Alt+Pfeil runter öffnen bereits den Dialog.
OnKeyPressTKeyPressEvent (Sender: TObject; var Key: Char)Zeichen eingegeben; Key := #0 verwirft es. Praxis: Um Zeichen abzuweisen, die in Windows-Pfaden nicht erlaubt sind (z. B. * ? " < > |): Key := #0.
OnKeyUpTKeyEvent (Sender: TObject; var Key: Word; Shift: TShiftState)Taste losgelassen. Praxis: Selten nötig; z. B. um nach dem Tippen verzögert eine Vorschau zu laden. Für Textänderungen ist OnChange der richtige Ort.
OnClickTNotifyEvent (Sender: TObject)Klick mit der linken Maustaste, Leertaste/Enter bei Buttons oder Auslösen per Zugriffstaste. Bei Listen, Baum, Grid, Auswahlgruppen und Aufklapp-Auswahlfeldern (ComboBox, ColorPicker, ColumnComboBox, CheckComboBox) meldet OnClick wie in der VCL die Auswahl durch den Anwender. Praxis: Selten nötig, ein Klick setzt nur den Textcursor. Für den Knopf im Feld OnBeforeDialog nehmen, nicht OnClick.
OnDblClickTNotifyEvent (Sender: TObject)Doppelklick mit der linken Maustaste. Controls, bei denen schnelle Klicks einzeln zählen (Button, CheckBox, ToggleSwitch, Rating, ToolBar …), haben es wie TButton nicht. Praxis: Um z. B. die gewählte Datei per Doppelklick im zugehörigen Programm zu öffnen (ShellExecute), wenn das Feld schon einen Pfad enthält.
OnMouseDownTMouseEvent (Sender: TObject; Button: TMouseButton; Shift: TShiftState; X, Y: Integer)Maustaste über dem Control gedrückt. Praxis: Selten für Dateifelder; Markieren und Knopf erledigt das Feld selbst.
OnMouseMoveTMouseMoveEvent (Sender: TObject; Shift: TShiftState; X, Y: Integer)Maus über dem Control bewegt. Praxis: Selten nötig; feuert bei jeder Mausbewegung. Hinweise zeigt man besser über Hint.
OnMouseUpTMouseEvent (Sender: TObject; Button: TMouseButton; Shift: TShiftState; X, Y: Integer)Maustaste über dem Control losgelassen. Praxis: Gegenstück zu OnMouseDown; beim Dateifeld selten gebraucht.
OnMouseEnterTNotifyEvent (Sender: TObject)Die Maus ist in das Control hineinbewegt worden. Praxis: Um beim Überfahren den vollständigen Pfad in einer Statuszeile zu zeigen, wenn er im Feld abgeschnitten ist.
OnMouseLeaveTNotifyEvent (Sender: TObject)Die Maus hat das Control verlassen. Praxis: Gegenstück zu OnMouseEnter: die Pfadanzeige in der Statuszeile wieder leeren.
OnMouseWheelTMouseWheelEvent (Sender: TObject; Shift: TShiftState; WheelDelta: Integer; MousePos: TPoint; var Handled: Boolean)Mausrad gedreht; Handled := True verhindert das Standard-Scrollen. Praxis: Selten für Dateifelder; Handled := True verhindert, dass der Parent scrollt.
OnMouseActivateTMouseActivateEvent (Sender: TObject; Button: TMouseButton; Shift: TShiftState; X, Y, HitTest: Integer; var MouseActivate: TMouseActivate)Mausklick auf ein noch inaktives Fenster; legt fest, ob es aktiviert wird. Praxis: Nur in Spezialfällen (Werkzeugfenster, die beim Klick nicht aktiv werden sollen); sonst nicht belegen.
OnContextPopupTContextPopupEvent (Sender: TObject; MousePos: TPoint; var Handled: Boolean)Vor dem Kontextmenü; Handled := True unterdrückt das Standardmenü. Praxis: Um das Kontextmenü vor dem Öffnen anzupassen, z. B. „Im Explorer zeigen“ nur bei vorhandener Datei freigeben.
OnDragDropTDragDropEvent (Sender, Source: TObject; X, Y: Integer)Ein gezogenes Objekt wurde über dem Control losgelassen. Nutzung: Source ist das gezogene Control; X, Y die Position im Control. Praxis: Für VCL-Drag & Drop innerhalb der Anwendung, z. B. einen Eintrag aus einer Liste „Zuletzt verwendet“ aufs Feld ziehen und dessen Pfad übernehmen. Dateien aus dem Explorer nimmt AcceptDrop an.
OnDragOverTDragOverEvent (Sender, Source: TObject; X, Y: Integer; State: TDragState; var Accept: Boolean)Ein Objekt wird über dem Control gezogen; Accept := True erlaubt das Ablegen. Praxis: Zusammen mit OnDragDrop: Accept := Source = lstZuletzt erlaubt das Ablegen nur aus der passenden Liste.
OnStartDragTStartDragEvent (Sender: TObject; var DragObject: TDragObject)Beginn des Ziehens dieses Controls; hier kann ein eigenes DragObject gesetzt werden. Praxis: Nur wenn das Feld selbst gezogen wird (DragMode = dmAutomatic); beim Dateifeld praktisch nie.
OnEndDragTEndDragEvent (Sender, Target: TObject; X, Y: Integer)Ziehen dieses Controls beendet (abgelegt oder abgebrochen; Target = nil bei Abbruch). Praxis: Gegenstück zu OnStartDrag; beim Dateifeld praktisch nie gebraucht.
